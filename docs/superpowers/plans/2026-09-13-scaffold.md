# Le Truc Atelier Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scaffold the Le Truc Atelier app: Bun-powered dev server, a demo Le Truc component proving the serve → enhance → react loop, jsdom-based tests, and typecheck/lint tooling.

**Architecture:** Static HTML shell served by a small `Bun.serve` script using Bun's native HTML imports (dev-mode on-the-fly bundling of the TS module graph and CSS). App code lives in `src/` as Le Truc components registered via `defineComponent` (side-effect imports from `src/main.ts`). Tests run on `bun test` with jsdom globals preloaded via `bunfig.toml`.

**Tech Stack:** Bun 1.3, TypeScript, @zeix/le-truc 2.6, jsdom, Biome.

## Global Constraints

- Bun is the only package manager / dev server / test runner — no Vite, no npm scripts beyond wrapping bun/tsc/biome.
- Test DOM is **jsdom** (NOT happy-dom — DOMPurify compatibility requirement).
- Demo components use the `demo-` prefix (e.g. `demo-greeter`).
- Dev server port: **5173**.
- Dev server lives in `server/dev.ts` using `Bun.serve` with HTML imports (mirrors le-truc repo layout).
- Code style: Biome, **tabs**, single quotes (matches le-truc codebase).
- TypeScript strict, `tsc --noEmit` for type checking (Bun does not typecheck).
- Runtime dependency: `@zeix/le-truc` only. devDependencies: `typescript`, `@types/bun`, `jsdom`, `@biomejs/biome`.
- Commit after every task.

### Task 2: Test infrastructure — jsdom globals for bun test

**Files:**
- Create: `src/test/setup.ts`
- Create: `src/test/setup.test.ts`
- Create: `bunfig.toml`

**Interfaces:**
- Consumes: `jsdom` devDependency (Task 1).
- Produces: every test file runs with jsdom `window`, `document`, `customElements`, DOM constructors (`Event`, `HTMLElement`, …) on `globalThis` — including jsdom's `Event` identity, so `new Event("input")` instances pass jsdom `dispatchEvent` brand checks.

- [ ] **Step 1: Write the smoke test (fails first — no globals yet)**

Create `src/test/setup.test.ts`:
```ts
describe('jsdom test environment', () => {
	it('provides browser globals', () => {
		expect(typeof window).toBe('object')
		expect(document).toBeInstanceOf(Document)
		expect(customElements).toBeDefined()
		expect(new Event('input')).toBeInstanceOf(Event)
	})
})
```

- [ ] **Step 2: Run test to verify it fails**

Run: `bun test src/test/setup.test.ts`
Expected: FAIL — `window` is undefined / `Document` is not defined.

- [ ] **Step 3: Write the preload setup**

Create `src/test/setup.ts`:
```ts
import { JSDOM } from 'jsdom'

const dom = new JSDOM('<!DOCTYPE html><html><body></body></html>', {
	url: 'http://localhost:5173/',
	pretendToBeVisual: true,
})

for (const key of Object.getOwnPropertyNames(dom.window)) {
	if (key === 'globalThis') continue
	Object.defineProperty(globalThis, key, {
		value: Reflect.get(dom.window, key),
		configurable: true,
		writable: true,
	})
}
```

Overwriting (not skipping) existing globals is deliberate: Bun ships its own `Event`/`EventTarget` implementations, and jsdom's `dispatchEvent` brand-checks its own `Event` — mixed identities make component event tests fail in confusing ways. `console`/timers being replaced by jsdom's is harmless under `bun test`.

- [ ] **Step 4: Register the preload in bunfig.toml**

Create `bunfig.toml`:
```toml
[test]
preload = ["./src/test/setup.ts"]
```

- [ ] **Step 5: Run test to verify it passes**

Run: `bun test src/test/setup.test.ts`
Expected: PASS (1 test).

- [ ] **Step 6: Commit**

```bash
git add bunfig.toml src/test
git commit -m "test: register jsdom globals for bun test"
```

### Task 3: `demo-greeter` component (TDD)

**Files:**
- Create: `src/components/demo-greeter.test.ts`
- Create: `src/components/demo-greeter.ts`

**Interfaces:**
- Consumes: jsdom globals from Task 2 preload; `defineComponent`, `bindText` from `@zeix/le-truc`.
- Produces: module `src/components/demo-greeter.ts` with side-effect registration of `<demo-greeter>`. Expected markup consumed by the component (used again in Task 4's index.html):

```html
<demo-greeter>
	<label for="name">Your name</label>
	<input id="name" name="name" type="text" />
	<p>Hello, <output for="name">World</output>!</p>
</demo-greeter>
```

Reactive property: `name: string` (initial: current `<output>` text or `'World'`).

- [ ] **Step 1: Write the failing test**

Create `src/components/demo-greeter.test.ts`:
```ts
import './demo-greeter'

describe('demo-greeter', () => {
	const settle = () => new Promise<void>((resolve) => setTimeout(resolve, 0))

	it('greets with the entered name', async () => {
		document.body.innerHTML = `
			<demo-greeter>
				<label for="name">Your name</label>
				<input id="name" name="name" type="text" />
				<p>Hello, <output for="name">World</output>!</p>
			</demo-greeter>
		`
		const input = document.querySelector<HTMLInputElement>('demo-greeter input')!
		const output = document.querySelector('demo-greeter output')!

		expect(output.textContent).toBe('World')

		input.value = 'Ada'
		input.dispatchEvent(new Event('input'))
		await settle()

		expect(output.textContent).toBe('Ada')
	})
})
```

Note: `settle()` waits one macrotask so any microtask-batched reactive effects flush before the assertion. If the scheduler turns out to use `requestAnimationFrame`, raise the delay to ~20 ms (`pretendToBeVisual` provides rAF).

- [ ] **Step 2: Run test to verify it fails**

Run: `bun test src/components/demo-greeter.test.ts`
Expected: FAIL — `<demo-greeter>` is not a registered custom element, output stays `'World'` after the input event.

- [ ] **Step 3: Implement the component**

Create `src/components/demo-greeter.ts` (mirrors the le-truc quick-start idiom):
```ts
import { bindText, defineComponent } from '@zeix/le-truc'

defineComponent('demo-greeter', ({ expose, first, on, watch }) => {
	const output = first('output', 'Needed to display the greeting.')
	const fallback = output.textContent || ''

	expose({ name: fallback })

	const input = first('input', 'Needed to enter the name.')
	on(input, 'input', () => ({ name: input.value || fallback }))
	watch('name', bindText(output))
})
```

- [ ] **Step 4: Run test to verify it passes**

Run: `bun test src/components/demo-greeter.test.ts`
Expected: PASS (1 test). If the final assertion still sees `'World'`, the effect is rAF-scheduled — raise `settle` to 20 ms and re-run.

- [ ] **Step 5: Commit**

```bash
git add src/components
git commit -m "feat: add demo-greeter component proving the reactivity loop"
```

### Task 4: Dev server + app shell

**Files:**
- Create: `server/dev.ts`
- Create: `index.html`
- Create: `src/main.ts`
- Create: `src/styles/main.css`

**Interfaces:**
- Consumes: `src/components/demo-greeter.ts` side-effect registration (Task 3); markup contract from Task 3.
- Produces: `bun run dev` serves the app at `http://localhost:5173/` with on-the-fly TS bundling. `src/main.ts` is the app entry that future components get imported into.

- [ ] **Step 1: Write the dev server**

Create `server/dev.ts`:
```ts
import index from '../index.html'

const server = Bun.serve({
	port: 5173,
	development: true,
	routes: {
		'/': index,
	},
})

console.log(`Le Truc Atelier dev server running at ${server.url}`)
```

`development: true` makes Bun bundle the HTML's `<script type="module">` graph (TypeScript included) and CSS on the fly, serve everything with dev error overlays, and live-reload on change.

- [ ] **Step 2: Write the app shell**

Create `index.html`:
```html

		<title>Le Truc Atelier</title>

		<script type="module" src="/src/main.ts"></script>
```
